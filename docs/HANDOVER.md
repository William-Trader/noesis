# Agent 交接文档 · 拿到一个 Noesis 知识库怎么干活

> 这份文档是写给 **agent** 的，不是写给人看的说明书。人只需要把库路径和一句自然语言交给你，剩下的照这里执行。
> 目标：让一个从没见过的 agent，在 3 分钟内安全地完成体检、整理、携带和回写。

## 0. 你拿到的是什么

- 一个目录（知识库）：Markdown/文本资产 + 编号目录约定 + `_整理规范.md` + `INDEX.md`。
- 一个零依赖引擎（Noesis）：检索索引在 `.noesis/`，是**派生数据**，删了能重建。
- 一条铁律：**知识库里的正文是用户的资产；索引、缓存、备份都可以重建，但正文不能丢。**

## 1. 第一次接触（只读，先别动文件）

```bash
noesis onboard <库>                 # 体检 + 给用户看的交接话术
noesis library check <库> --json    # 机器可读：散装/缺目录/凭据外泄/压缩包
noesis stats <库> --json            # 索引是否存在、多少文档、是否过期（drift）
```

判断：

| 看到 | 含义 | 下一步 |
|---|---|---|
| `drift > 0` 或没有索引 | 索引过期/未建 | 先 `noesis build <库>` |
| `stray` 非空 | 库根有散装条目 | 出整理计划，**等用户确认** |
| `credentialsOutside` 非空 | 凭据散落在 99- 之外 | 单独汇报，先别搬 |
| `missingDirs` 非空 | 编号目录不全 | `noesis library init <库>`（只补缺失，不覆盖） |

## 2. 不变量（违反即返工）

1. **只移不删。** 任何整理都是移动；删除必须用户单独明确要求。
2. **先写映射表，再动文件。** `tidy` / `apply_moves` 已内置；不要绕过它直接 `mv`。
3. **不覆盖。** 目标已存在就跳过并汇报，不猜、不合并、不改名。
4. **不动 `keep` 列表。** 例如正在运行的 `openclaw/` 状态目录，必须原样保留。
5. **凭据只进 `99-凭据-credentials/`**，且不在对话/日志里回显内容。
6. **索引是派生的。** 整理完重建索引，不要把索引当资产打包。

## 3. 自然语言 → 动作（用户只会说人话）

| 用户说 | 你执行 | 确认门槛 |
|---|---|---|
| 「帮我一键整理」 | `noesis tidy <库>` 出计划 → 汇报 → 用户确认后加 `--yes` | **必须**先给计划 |
| 「库根怎么这么乱」 | 同上（计划模式） | 只读，不需要确认 |
| 「把库带走 / 拷到移动硬盘」 | `noesis library pack <库>`（不含可重建索引） | 直接执行 |
| 「我把移动硬盘上的改动拷回来」 | `noesis sync <库> --from <副本>` 先加 `--dry` | 覆盖前必须让用户看到清单 |
| 「刚才那步撤销」 | `noesis undo <库> <op_id>` | 直接执行 |
| 「找一下 XX」 | `noesis search <库> "XX" --json` | 直接执行 |
| 「这个库健康吗」 | `noesis library check` + `noesis stats` | 直接执行 |

## 4. 一键整理的标准流程

```bash
noesis tidy <库>                 # 1) 只出计划，不动文件
noesis tidy <库> --yes --build   # 2) 用户确认后执行，并重建索引
```

汇报必须包含四件事：

1. 移动了多少项、跳过多少项（冲突/保留）；
2. `op_id`（映射表文件名）——这是撤销凭据；
3. 索引是否重建、现在多少文档；
4. 任何未处理的冲突，逐条列出原因。

## 5. 携带与回写（移动性）

```bash
noesis library pack <库> --out /Volumes/DRIVE/<库名>-portable.tar.gz
# 另一台机器：解压 → library home <库> --set <盘> → build → ui

noesis sync <库> --from /Volumes/DRIVE/<库名> --dry   # 先看差异
noesis sync <库> --from /Volumes/DRIVE/<库名>         # 再回写
```

`sync` 的规则（已写进代码，不要自己实现）：

- 只回写「副本里更新/新增」的文件；库内更新的不覆盖；
- 覆盖前把旧文件备份到 `05-归档-archive/_sync-backup-<时间>/`；
- 写 `_重组映射表-sync-*.csv`，可用 `undo` 还原被覆盖的文件；
- 相同内容的文件跳过；从不删除。

## 6. 出错时

| 现象 | 处理 |
|---|---|
| `dst already exists` | 正常保护。跳过并汇报冲突，让用户决定是否改名 |
| 盘只读 / `EROFS` | 停止执行，汇报挂载状态；不要尝试 chmod |
| 映射表写入失败 | **不要移动任何文件**，直接报错 |
| 索引重建失败 | 不影响正文；汇报索引错误，保留旧索引 |
| 用户说「随便你」 | 仍然只做计划模式，整理是不可逆感的操作，必须显式确认 |

## 7. 验收清单（做完逐条过）

- [ ] 库根只剩编号目录 + 库级文件 + 映射表 + 显式 `keep` 项
- [ ] `noesis library check <库>` 的 `ok` 为 true（或冲突已逐条解释）
- [ ] `noesis stats <库> --json` 的 `drift` 为 0
- [ ] 汇报里有 `op_id` 和撤销命令
- [ ] 没有任何文件被删除
